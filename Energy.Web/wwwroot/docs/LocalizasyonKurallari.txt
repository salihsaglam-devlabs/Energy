13. LOCALIZATION VE MAGIC STRING STANDARDI

Sistemde kullanıcıya görünen veya dışarı dönen tüm metinler localization üzerinden yönetilecek.

Bu projede hardcoded/sabit mesaj kullanımı kabul edilmez. UI, API, validation, exception, notification, menu, permission açıklaması, grid başlığı, buton metni, placeholder, tooltip, toast mesajı, modal başlığı, confirm mesajı, hata mesajı, başarı mesajı ve uyarı mesajı dahil olmak üzere kullanıcıya temas eden her metin localization catalog/resource dosyalarında tanımlanmalıdır.

Kesin kurallar:

* Kullanıcıya görünen hiçbir metin C#, Razor, JavaScript, HTML veya JSON içinde hardcoded yazılmayacak.
* Magic string mesaj kullanılmayacak.
* `"Kayıt başarıyla oluşturuldu"`, `"Silmek istediğinize emin misiniz?"`, `"Yetkiniz yok"`, `"Validation failed"`, `"Save"`, `"Delete"`, `"Edit"` gibi metinler doğrudan kod içinde bulunmayacak.
* Backend response mesajları localization key üzerinden dönecek.
* Validation mesajları localization key üzerinden üretilecek.
* Exception mesajları localization key üzerinden üretilecek.
* API error response mesajları localization destekli olacak.
* DevExtreme grid kolon başlıkları localization üzerinden gelecek.
* DevExtreme button textleri localization üzerinden gelecek.
* DevExtreme lookup placeholder/search/noDataText/loadingText gibi tüm UI metinleri localization üzerinden gelecek.
* Menü adları localization üzerinden gelecek.
* Sayfa başlıkları localization üzerinden gelecek.
* Modal/popup başlıkları localization üzerinden gelecek.
* Toast/notification mesajları localization üzerinden gelecek.
* Confirm dialog metinleri localization üzerinden gelecek.
* JavaScript içinde kullanıcıya görünen metin varsa localization helper üzerinden alınacak.
* Razor içinde kullanıcıya görünen metin varsa IHtmlLocalizer/IStringLocalizer veya merkezi localization helper üzerinden alınacak.
* API içinde kullanıcıya dönen metin varsa ILocalizationService veya merkezi localization service üzerinden alınacak.
* Permission Name/Description alanları localization key ile ilişkilendirilecek.
* Menu DisplayName alanları localization key ile ilişkilendirilecek.
* Lookup/reference display metinleri veriden geliyorsa veri gösterilir; sistemsel label, status açıklaması veya enum display name gerekiyorsa localization üzerinden üretilecek.
* Enum display değerleri hardcoded olmayacak; localization key üzerinden gösterilecek.
* Frontend ve backend aynı localization key standardını kullanacak.
* Türkçe ve İngilizce resource dosyaları birlikte güncellenecek.
* Eksik localization key varsa sessiz geçilmeyecek; coverage raporunda listelenecek.
* Kodda kullanıcıya görünen hardcoded metin kalırsa bu kabul kriteri başarısız sayılır.

Teknik uygulama standardı:

* Energy.Localization merkezi localization kaynağı olarak kullanılacak.
* SharedResource.tr-TR.resx ve SharedResource.en-US.resx eksiksiz güncellenecek.
* C# tarafında localization key sabitleri merkezi bir sınıfta tutulacak.
* JavaScript tarafında localization metinleri merkezi endpoint veya bootstrap localization object üzerinden yüklenecek.
* JS içinde doğrudan Türkçe/İngilizce metin yazılmayacak.
* Razor view içinde doğrudan Türkçe/İngilizce metin yazılmayacak.
* Controller, Service, Handler ve Validator içinde doğrudan kullanıcı mesajı yazılmayacak.
* Tüm response mesajları localization key ile üretilecek.
* Tüm validator mesajları localization key ile üretilecek.
* Tüm exception mesajları localization key ile üretilecek.

Örnek yanlış kullanım:

throw new Exception("Kayıt bulunamadı");
return BadRequest("Yetkiniz yok");
button.Text = "Kaydet";
toast.success("Kayıt başarıyla oluşturuldu");

Örnek doğru kullanım:

throw new NotFoundException(LocalizationKeys.Common.Messages.NotFound);
return BaseResponse.Fail(LocalizationKeys.Common.Messages.Forbidden);
button.Text = L("Common.Actions.Save");
notification.success(L("Modules.Procurement.PurchaseOrder.Messages.Created"));

Son kontrol:

Build işleminden önce kod tabanı taranacak ve kullanıcıya görünen hardcoded metinler tespit edilip localization’a taşınacak.
