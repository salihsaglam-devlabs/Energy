MEDIATR / CQRS KORUMA VE UYGULAMA STANDARDI

Bu projede mevcut MediatR altyapısı kaldırılmayacak. Mevcut projede MediatR, CQRS, Command, Query, Handler, PipelineBehavior veya benzeri yapılar varsa bunlar silinmeyecek; kurumsal mimariye uygun şekilde yeniden düzenlenecek ve kullanılmaya devam edilecek.

MediatR bu projenin Application katmanındaki use-case orchestration standardıdır.

Kurallar:

* MediatR kaldırılmayacak.
* IMediator kullanımı korunacak.
* Mevcut Command, Query ve Handler yapıları silinmeyecek; sadece modül/entity/süreç/rapor klasör yapısına uygun hale getirilecek.
* API controller’lar doğrudan Infrastructure service çağırmayacak.
* API controller’lar mümkün olduğunca IMediator.Send(...) üzerinden Application use-case’lerini çalıştıracak.
* Business logic controller içine yazılmayacak.
* Handler içine doğrudan karmaşık iş akışı yığılmayacak.
* Handler, ilgili entity service, process service, report service veya domain/application rule sınıflarını orkestre edecek.
* Generic Command/Query/Handler mimarisi kurulmayacak.
* CreateEntityCommand<T>, UpdateEntityCommand<T>, GenericCrudHandler<T> gibi tüm sistemi generic handler ile yöneten yapılar kullanılmayacak.
* Her entity, süreç ve rapor için açık, okunabilir ve tek sorumluluklu Command/Query/Handler dosyaları oluşturulacak.
* MediatR pipeline behavior yapısı validation, logging, authorization, transaction ve exception handling için kullanılabilir.
* FluentValidation kullanılıyorsa validator’lar MediatR validation pipeline üzerinden çalıştırılacak.
* Transaction gerektiren süreçlerde transaction behavior veya process service içi transaction standardı korunacak.
* CancellationToken tüm MediatR handler’larında kullanılacak.
* Handler’lar Application katmanında kalacak.
* Handler’lar Infrastructure, Web veya Api katmanına bağımlı olmayacak.
* Infrastructure sadece Application interface’lerini implemente edecek.
* Web tarafı yine Web API Client üzerinden API ile konuşacak; Web controller doğrudan MediatR veya DbContext kullanmayacak.

API controller standardı:

* Controller sadece request alır.
* Permission kontrolü yapılır.
* Request ilgili Command veya Query’ye map edilir.
* IMediator.Send(commandOrQuery, cancellationToken) çağrılır.
* BaseResponse sonucu döndürülür.

Örnek akış:

PurchaseOrdersController
-> IMediator.Send(CreatePurchaseOrderCommand)
-> CreatePurchaseOrderCommandHandler
-> IPurchaseOrderService
-> Infrastructure PurchaseOrderService
-> AppDbContext

Süreç örneği:

GoodsReceiptProcessController
-> IMediator.Send(ExecuteGoodsReceiptCommand)
-> ExecuteGoodsReceiptCommandHandler
-> IGoodsReceiptProcessService
-> Infrastructure GoodsReceiptProcessService
-> Transaction
-> AppDbContext

MediatR kayıtları:

* Energy.Application assembly’sindeki tüm handler’lar dependency injection’a eklenecek.
* PipelineBehavior kayıtları merkezi DependencyInjection içinde yapılacak.
* ValidationBehavior, LoggingBehavior, AuthorizationBehavior ve TransactionBehavior gerekiyorsa korunacak veya yeniden kurulacak.
* Mevcut MediatR NuGet paketleri kaldırılmayacak.
* Mevcut MediatR referansları bozulmayacak.
* Build sonunda MediatR handler registration hatası kalmayacak.

Kabul kriteri:

* Proje sonunda MediatR aktif olarak kullanılmaya devam etmeli.
* API controller’ların ana use-case çağrıları IMediator üzerinden yapılmalı.
* Command/Query/Handler yapıları modül bazlı düzenlenmiş olmalı.
* Hiçbir MediatR dosyası gerekçesiz silinmemeli.
* Mevcut MediatR davranışı yeni mimariye uyarlanmalı.
* Coverage raporunda MediatR/CQRS kapsamı ayrıca belirtilmeli.
