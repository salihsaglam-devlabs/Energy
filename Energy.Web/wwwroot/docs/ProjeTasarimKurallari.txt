Route standardı:

GET    /api/v1/{module-name}/{entity-name}
GET    /api/v1/{module-name}/{entity-name}/{id}
GET    /api/v1/{module-name}/{entity-name}/lookup
POST   /api/v1/{module-name}/{entity-name}
PUT    /api/v1/{module-name}/{entity-name}/{id}
DELETE /api/v1/{module-name}/{entity-name}/{id}

POST   /api/v1/{module-name}/processes/{process-name}
GET    /api/v1/{module-name}/processes/{process-name}/{id}
POST   /api/v1/{module-name}/processes/{process-name}/approve
POST   /api/v1/{module-name}/processes/{process-name}/reject
POST   /api/v1/{module-name}/processes/{process-name}/cancel

GET    /api/v1/{module-name}/reports/{report-name}
GET    /api/v1/{module-name}/reports/{report-name}/export

Lookup endpoint standardı:

- Basit entity lookup için GET /api/v1/{module-name}/{entity-name}/lookup kullanılabilir.
- Lookup karmaşıksa veya birden fazla lookup varyasyonu gerekiyorsa Lookups/{EntityName}LookupController kullanılabilir.
- Hangi yaklaşım seçilirse seçilsin route, permission, Swagger group ve Web API Client tarafı tutarlı olacak.

Her ana iş entity controller minimum şunları destekleyecek:

- GET list
- GET detail
- GET lookup
- POST create
- PUT update
- DELETE delete veya soft-delete
- PATCH status gerekiyorsa

8. TABLO EKRANI STANDARDI

Excel’deki 134 tablonun her biri sistemde yönetilebilir olmalı.

Ancak her tablo aynı seviyede doğrudan bağımsız CRUD ekranı olmak zorunda değildir. Aşağıdaki ayrım uygulanacak:

A) Ana iş tabloları:
- Bağımsız Index/Form/Detail ekranı olacak.
- CRUD veya iş kuralına göre Create/Update/Delete/Cancel destekleyecek.

B) Detay tabloları:
- Parent ekran içinde detail grid, tab panel veya master-detail olarak yönetilebilir.
- Gerekirse ayrı ekran da oluşturulabilir.
- Kullanıcıyı gereksiz şekilde ayrı detay tablosu ekranlarına zorlamayacak.

C) Junction / mapping tabloları:
- Genellikle parent ekran içindeki seçim/listbox/tagbox/detail grid üzerinden yönetilecek.
- Gerekmedikçe bağımsız CRUD ekranı olmayacak.
- Ancak yönetim ihtiyacı varsa ayrı ekran oluşturulabilir.

D) Log / audit / history tabloları:
- Genellikle read-only liste/detail ekranı olacak.
- Create/Update/Delete kullanıcıya açılmayacak.
